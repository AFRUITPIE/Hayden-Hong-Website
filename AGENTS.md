# AGENTS.md

This file provides guidance to AI coding agents when working with code in this repository.

## Commands

```bash
bun install          # Install dependencies
bun dev              # Start development server (localhost:3000)
bun build            # Production build
bun test             # Run Playwright E2E tests (auto-starts dev server)
bun types:check      # Type-check (next typegen + tsc --noEmit)
```

Playwright runs against `localhost:3000` and starts the dev server automatically.

## Architecture

This is a personal website at [haydenhong.com](https://haydenhong.com) built with **Next.js App Router** and **shadcn/ui**, with all site content authored as MDX.

**Content flow:** MDX files in `content/docs/` are read twice, for two different purposes:

1. `lib/content.ts` scans them on the filesystem for _metadata_ — frontmatter, the sidebar tree, the table of contents, and plain text.
2. `@next/mdx` (configured in `next.config.mjs`) compiles them for _rendering_; the page route imports the matching file dynamically.

Both feed the single catch-all route at `app/(site)/[[...slug]]/`.

**Key structural pieces:**

- `app/(site)/` — Route group for all content pages; `layout.tsx` wraps with the shadcn sidebar
- `app/api/search/` — Prerendered search index; the Command dialog ranks results client-side
- `app/og/` — Open Graph image generation for SEO
- `app/llms-full.txt/` — Serves full site content for LLM context
- `lib/content.ts` — Content layer: page list, page tree, TOC, plain text, OG image URLs
- `lib/search-filter.ts` — Pure ranking helper shared by the search dialog
- `mdx-components.tsx` — MDX typography plus the `Card`/`Callout`/`Steps` globals available to all content
- `components/ui/` — shadcn/ui components, generated by its CLI; prefer regenerating over hand-editing
- `components/mdx/` — Custom MDX components (e.g., `mermaid.tsx` for diagram rendering)

Sidebar order and section titles come from the `meta.json` files in `content/docs/`.

**Styling:** Tailwind CSS v4 with the shadcn token set — no separate `tailwind.config.ts`; configuration is in `postcss.config.mjs` and `app/global.css`. shadcn is configured for the Base UI component base (`components.json`), so components compose with a `render` prop rather than `asChild`.

**Theming:** Light/dark follows the operating system via `next-themes`; there is no in-app toggle.

**Tooling:** Bun as runtime/package manager (version managed via `mise.toml`). Prettier runs automatically on commit via Husky + lint-staged.
